# Style Guide: packet-handler

## Unique Conventions

### Top-Level Function, Not a Class
`handlePacket` is a top-level `fun`, not a method on a class:
```kotlin
fun handlePacket(session: Session, packet: Packet, coroutineScope: CoroutineScope) { ... }
```

### runCatching Around the Entire when Block
The entire dispatch is wrapped in `runCatching { ... }.onFailure { error -> println("...") }` so that one bad packet does not kill the listening loop.

### Private Top-Level Helper Functions
Each packet type's handling is extracted into its own private top-level function named `handleX(session, packet, ...)`:
```kotlin
private fun handleUserConnected(...) { ... }
private fun handleUserDisconnected(...) { ... }
private fun handleChatMessageReceived(...) { ... }
// ...
```

This keeps the main `when` block short and readable.

### System Message Prefix "Sistema"
Messages generated by the client itself (user joined, user left, disconnected) use `username = "Sistema"` and content in Brazilian Portuguese.

### Coroutine Launch for Async Handlers
Handlers that require `suspend` (ICE candidate, SDP description) use `coroutineScope.launch { runCatching { ... } }`:
```kotlin
private fun handleIceCandidateReceived(...) = coroutineScope.launch {
    runCatching {
        session.peerConnections.updateIceCandidate(...)
    }.onFailure { println("Failed to add ICE candidate: ${it.message}") }
}
```

### Ignored Packets Have Empty Branches
Packets that require no client-side action have explicit empty branches in the `when` to confirm they have been considered:
```kotlin
is Packet.ScreenShareStarted -> {}
is Packet.ScreenShareStopped -> {}
```
